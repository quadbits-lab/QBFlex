# Contribute to the platform

## Start with the owning contract

Locate the existing route/type/error in `packages/contracts`, implementation in `apps/api` and owner operation in `packages/database`. Transport handlers should validate input and dispatch, not invent a parallel policy engine. Database/query/policy changes must preserve parameterized SQL, exposure checks, transaction boundaries, precision serialization, signed cursors and transactional outbox behavior. Keep counts, returned rows, related reads, RPC and events under the same authorization rules.

Worker changes must retain private authentication, bounded jobs, leases, cleanup and retention; owner timeouts/crashes must reject uncertain calls and preserve acknowledged durability. Avoid enabling P1 adapters as a side effect of compatibility spikes. Add/update the capability registry only when the feature and its release tests exist.

For SDK changes inspect generated declarations and packed consumers, preserving browser ESM and React-free Vanilla packages. React changes must retain provider boundaries, identity-scoped caches, cancellation, request-local SSR and subscription cleanup. Maintain shared-client behavior across both adapters. Regression tests should reproduce an observable security/lifecycle defect, not mirror implementation details.

## Studio, UI, branding and Docs

Follow inherited `AGENTS.md` TanStack Intent instructions: list local skills before substantial edits and load the package-specific skill relevant to the change. TanStack Start is isomorphic by default; keep private server work behind authenticated server functions/routes. Create request-local routers/caches and maintain hydration behavior. Shared `packages/ui` owns branding and components; use the supplied assets in their actual format and proportions. Section/navigation icons should remain accessible, decorative icons aria-hidden, and mobile drawers keyboard-operable.

Workspace selection is separate from protected navigation. If no workspace is selected, Studio shows the workspace switcher/onboarding. Details, avatar/archive/delete operate on the selected organization. Settings → Project edits the selected project's identity and quotas and can delete that project alone. Workspace delete cleans up only that organization's project IDs/storage prefixes; project delete cleans up only that project's branches, files, storage prefixes, and catalog rows. Never claim a deletion completed until branch directories, control records, and backend objects have been removed. Studio guards protected routes in `beforeLoad` using the router's request-local query client. Skip private SSR, verify the cookie after every successful auth ceremony, cancel stale reads and clear identity caches on sign-in/sign-out. Preserve local return URLs only; API failures belong on the retry screen. See `tests/studio-auth.test.ts` and `bun run test:studio-auth` for both local loopback hostnames. Route guards never replace API authorization.

Studio's request-local query client refreshes active queries after successful mutations through its global MutationCache callback. Custom successful submit/transfer handlers must await `refreshStudioQueries` instead of adding duplicate per-form invalidations. The helper cancels older reads, marks inactive views stale and does not turn an acknowledged write into a failure if a refresh read fails. Failed writes keep existing data/input; do not globally retrofit this behavior into application SDK caches.

Docs is independently deployable `apps/docs`, with repository-owned MDX, generated heading/search metadata, static prerendering, code-copy controls and shared UI. Update the relevant implemented guide and Studio Help route. Future architecture explanations must be marked planned and must not contain runnable examples implying support. Update code examples with actual declarations, not permissive fixtures hiding type incompatibilities. Run `docs:generate`, `docs:check` and the MDX example checker after public changes.

## Skill maintenance

`bun run skill:refresh` builds SDK declarations, extracts API routes/capabilities, SDK declarations, CLI help and test evidence, regenerates example database/RPC types from the bundled schema and updates source/file checksums. Curated security guidance remains a human-reviewed reference. `skill:check` compares generated output and provenance without rewriting, validates metadata and all local links, checks bundled imports/files and rejects missing/extra/tampered files. `skill:test` verifies detached checks/diagnostics, actual packaged SDK declarations/types, builds both portable applications, exercises isolated workflows and runs existing platform/lifecycle regression tests. It reports missing S3 configuration instead of claiming transfer verification.

`skill:pack` validates the bundle and writes a deterministic `dist/skills/qbflex-skills.zip` with one root directory. Archive extraction and checksum verification must work outside the source checkout. Never include `.env`, node_modules, raw credentials, personal filesystem paths or authoring-skill files. The bundle documents 0.1.0; changed compatibility requires refreshed sources and validation, not just editing a version label.

Finish with changed behavior, relevant passing checks, skipped/unverified paths and any required environment configuration. Local packaging and review are distinct from external deployment, publication and registry release.

## Specification1.1 foundations

The expanded release is incomplete. Private branch jobs now support encrypted payloads, bounded queues, deduplication, fenced leases/attempts, cancellation and explicit dead-letter replay through owner calls. Management exposes metadata only; internal executors authenticate and receive server-derived kind scopes (maintenance cannot claim push). Push replay is blocked pending campaigns. Experimental webhook integration now adds atomic outbox checkpoints, encrypted subscription/reference records, exact-branch non-bypass GET service-key scopes, real-engine SELECT revalidation/projection, fresh exact-body HMAC signatures, bounded rotation/retries, fixed-IP HTTPS dispatch and metadata-only Studio controls. Alert/push/drill executors remain required.

Policy-test write simulations use synthetic isolated fixtures with the actual engine; never forward user-provided privilege flags. Legacy read tests remain filtered. PATCH and DELETE forward expected revisions. Storage checksum metadata is optional; both upload surfaces stage bounded streams privately before S3 PUT. Branch archive v2 is streamed/authenticated and legacy branch checksums remain readable; control archives also stream with authenticated kind/digest/time metadata and retain incremental legacy JSON/base64 recovery. Offline restore holds the exclusive volume lease, verifies dependencies/migrations and revokes restored capabilities before replacement. Update generated routes/declarations and run negative HTTP/legacy tests for these paths.

Security Advisor now scans bounded metadata, reports severity/evidence/remediation and stores evidence-bound expiring acknowledgments. It samples no rows and never repairs grants.

Required but not implemented: full recovery/operations/alerts/Query Inspector, reviews/previews, full Advisor/simulator/webhook certification, native/offline/background/push SDK and toolkit, search/realtime debugger and all four optional WASM workers. Do not advertise their availability or include mock success examples.

The terminal logger uses the existing Elysia hooks and shared redaction for pretty/JSON output. Keep machine logs JSON in production/pipes, honor color controls, and preserve metrics when quieting successful polling. Never replace the allowlist with raw request/response logging.
