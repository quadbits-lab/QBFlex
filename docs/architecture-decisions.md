# M0 architecture decisions

The implementation follows the inherited TanStack Intent workflow and keeps exact compatible dependency releases in `package.json`/`bun.lock`.

| Decision         | Chosen implementation and evidence                                                                                                                                                                                                                                                                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Web applications | TanStack Start/Router with React 19; Studio SSR and Docs prerendering/builds are exercised in Linux images. Query owns remote state; Store owns Studio selection, Form owns onboarding, Table/Virtual own bounded grids. TanStack DB is deferred until live collection joins justify it.                                                                                        |
| Request runtime  | Elysia under Bun; native Bun WebSockets for an authenticated first-frame join, because project credentials must not be placed in URLs. Bounded GraphQL Yoga mounting succeeds in the compatibility spike; GraphQL stays P1.                                                                                                                                                     |
| PGlite           | Bun workers isolate synchronous branch SQL from the gateway. Native PGlite persistent filesystem durability is enabled and foreign keys are enforced, queues cap at 64, deadlines terminate ambiguous workers, and a local OS advisory file lock fences the API data volume. SIGKILL tests verify committed writes and transaction rollback. Distributed ownership is deferred. |
| Authentication   | Better Auth uses distinct platform/branch secrets, cookie prefixes and branch metadata. Session lookups are uncached for revocation. MFA, email delivery, scoped credentials and project/user/branch isolation have executable tests. Google/GitHub adapters are configured but live provider certification requires actual credentials.                                        |
| Policies         | One restricted AST compiler and transaction engine covers reads, counts, mutations, upserts, approved relationships, reviewed RPC and row-event visibility. Default exposure/policies deny access. SQL/file access is trusted administration and is outside application RLS.                                                                                                    |
| Event capture    | Managed transactional outbox triggers record committed row images. Current authorization is rechecked before projection. Deletes send only keys, cursors are bounded by retention, and reconnect can require resynchronization. Custom triggers/views/virtual tables are private.                                                                                               |
| Object backend   | S3 gateway plus branch metadata enforces owner/private and public-read access. Real-byte tests pass against a configured S3-compatible backend (e.g. RustFS). Resumable transfers/transforms/custom storage AST are P1; production backend certification remains deployment-specific.                                                                                           |
| Recovery         | PGlite datadir snapshots, authenticated encryption and checksums; isolated branch validation before explicit cutover. Control archives are separate and offline restore excludes sessions/revokes keys. S3 bytes and master-key escrow are independent operator responsibilities.                                                                                               |
| Browser SDKs     | One React-free ESM client drives both examples. React context owns a stable client and scoped Query cache; custom hooks bind to identity changes, cancellation and lifecycle cleanup. React Native and other adapters are deferred.                                                                                                                                             |
| Documentation    | Repository MDX, generated references/search/sitemap and prerendered HTML. Tutorials compile against actual exports; SDK consumers compile generated database/RPC types, including expected type failures.                                                                                                                                                                       |
| Vectors          | Vector product APIs remain planned. The former sqlite-vec compatibility spike is retired; PGlite does not enable vector APIs automatically.                                                                                                                                                                                                                                     |
| Operations       | Single-node worker-authenticated maintenance, explicit quotas, allowlisted structured logs and Prometheus metrics. Full distributed tracing, multi-node abuse controls, automatic failover and P1 job runners are future architecture.                                                                                                                                          |

P0 intentionally supports the documented PGlite/API subset. P1/P2 interfaces expose planned availability rather than mock success. The release remains local, and external publishing requires a separate release action.

## Checkpointed delivery and security diagnostics

Database webhooks are experimental. Owner-local subscription checkpoints and encrypted reference jobs commit in one transaction; a durable control marker is registered before creating a subscription so a crash cannot hide committed work from worker discovery. Executors poll only marked branches, retire transient owners before replacement and use private APIs, never another PGlite writer. Dispatch checks active exact-branch non-bypass GET service scopes and current shared SELECT policies/projection, then signs exact bytes with a fresh timestamp and stable event ID. Receiver deduplication remains mandatory; historical events retain 24 hours and expired checkpoints explicitly require resynchronization.

Outbound HTTPS screens all DNS answers, pins a validated IP, retains Host/SNI/certificate verification, denies redirects and forwards signature/content headers only. An operator allowlist maps exact HTTPS origins to fixed IPs, never wildcard DNS or TLS bypass. Known metadata destinations remain denied. Ten-second DNS/HTTPS deadlines and controlled codes bound handling; provider bodies do not enter telemetry. The existing worker delivery loop claims webhook jobs only; email, recovery and push executors remain separate work.

Security Advisor uses bounded static metadata heuristics, not another policy engine or production-row sampling. Findings bind severity/resource/evidence into stable IDs. Administrator acknowledgments expire within 30 days, remain visible and cannot survive changed evidence or branch restore. Additive control key-creation metadata preserves credential age after audit pruning and leaves legacy unknown ages explicit. Simulator hard execution budgets and full security/compatibility certification remain required.
