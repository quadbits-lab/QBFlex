## New source contracts

- Private branch tables `_qb_jobs` and `_qb_job_attempts` initialize idempotently within existing owners and are never application-exposed. Job payloads encrypted under a branch-derived key. No new PGlite mount/executor writer.
- Max64KiB payload,10,000 pending jobs,1–60second leases; webhook/email10attempts24h, push6attempts1h, recovery/maintenance3attempts24h. Terminal history and dedup keys expire after30days. Replay preserves event ID and records parent job; external receivers still deduplicate.
- Management `GET .../jobs`, `GET .../jobs/:job`, admin `POST .../jobs/:job/cancel` and `.../replay` (Idempotency-Key required). Metadata only. Push replay deliberately rejected until recipient-aware campaign retry exists. Typed `ManagementClient.jobs(projectId, branchId)` helpers.
- Internal `POST /internal/jobs/claim` and `/finish` require private worker credentials, immutable project/branch IDs and valid leases. Worker token can handle only non-push kinds. Optional distinct push token, enabled only by `QB_PUSH_ENABLED=true`, can handle only push kinds. Caller-supplied kind lists ignored. No generic submission endpoint. Webhook-only executor claims use a server-defined subset; private targets/produce/prepare/release support bounded discovery and transient owner retirement. Reverse proxy must continue rejecting `/internal/*`.
- Policy-test endpoint adds operation/fixtures/input/key/revision. Explicit simulation uses in-memory synthetic data, actual engine and no authentication token. Legacy requests still query real data under simulated application policies; privilege flags do not cross the boundary.
- `storage.upload(..., { checksum })` adds optional lowercase SHA256 intent metadata. Both management/application content uploads use private staging,120second cancellation/timeout,64KiB stream high-water marks, existing four-transfer ceiling and existing bucket/project quotas. Backends only receive validated staged files. Nativecrypto, no WASM dependency.
- Branch archive v2 uses authenticated magic/header/IV/ciphertext/tag and raw SHA256 with `sha256:` manifest prefix. Legacy branch IV/ciphertext/tag plus base64-text checksum remains readable. Control archives now use authenticated self-contained format2 and incrementally restore the legacy encrypted JSON/base64 format1. CLI checksum stays raw SHA256; format/size are additive. Offline restore validates dependencies/migrations, revokes credentials, creates a streamed rollback and fsyncs replacement while holding the volume lease. Backup/restore shares two-operation ceiling and120second stream deadline; startup sweeps recognized abandoned upload/branch-archive staging under the exclusive volume lease.

Rotations overlap 24 hours, attempts remain ten/24h, receivers deduplicate stable event IDs, and expired source events/gaps are explicitly rejected. ## Studio submission-refresh fix (6 October 2026)

Studio now owns refresh-on-success in its request-local MutationCache, rather than repeating per-form invalidations. Custom file transfers, project creation and authenticator/auth setup await the same helper. Older reads are cancelled before active queries refetch; inactive queries stay stale until navigation and disabled queries remain disabled. Read failures do not turn an acknowledged write into a failed submission. Application SDK consumers still own their cache invalidation; this is not a new document-management service.

`tests/studio-query-client.test.ts` adds five regressions for awaited list/summary refresh, stale-read cancellation even with an abort-ignoring transport, inactive/disabled queries, failed writes/reads and cache isolation.
