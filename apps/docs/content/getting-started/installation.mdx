# Install and run locally

## Requirements

Use pinned Bun 1.4.2. Native macOS development is the current development track; Windows uses WSL2/Docker, with native Windows execution experimental. A Docker-compatible engine is needed for optional Mailpit, bucket initialization and container verification. Object storage is separately supplied by you, such as RustFS; there is no bundled MinIO service.

```sh
bun install --frozen-lockfile
cp .env.example .env
```

Edit the new `.env` with your S3 endpoint/bucket/credentials and email provider selection. Do not commit it. Configure an endpoint reachable from the API process, then start native hot reload:

```sh
bun run dev
```

Studio runs on 7610, Docs on 7611 and API on 7612. The terminal startup panel confirms readiness and shows the service links; see [terminal logging](/docs/self-hosting/monitoring#terminal-display) for display controls. Each app has independent workspace commands. Database files and generated local secrets live under ignored `.data`.

The launcher checks occupied ports and waits for the API to create/accept its worker credential. If the full Docker stack owns these ports, use its running apps or stop those application services before hot reload:

```sh
docker compose stop studio docs api worker
bun run dev
```

This preserves database volumes and separately managed storage. Native `.data` and Docker's database volume are separate installations. A worker must use its API's `QB_DATA_DIR` or securely supplied `QB_WORKER_TOKEN`; never create/copy a token file to bypass startup checks.

## Object storage and email

Run RustFS or your chosen provider independently. For native development `.env.example` assumes an S3 endpoint at `http://127.0.0.1:9000`. [Storage configuration](/docs/storage/files) explains the remaining variables and container addressing.

For local SMTP inbox capture:

```sh
docker compose up -d mailpit
```

Select `QB_MAIL_PROVIDER=smtp`, `QB_SMTP_HOST=127.0.0.1` and `QB_SMTP_PORT=7615` for native API development. Mailpit's inbox is on 7616. Alternatively configure [Resend and React Email](/docs/authentication/email); explicit SMTP selection overrides a present Resend key.

The optional `storage-init` service runs inside Docker, so use a container-reachable endpoint when invoking it:

```sh
QB_S3_ENDPOINT=http://host.docker.internal:9000 docker compose run --rm --build storage-init
```

The service needs your configured bucket/credentials; provider provisioning failure is not a healthy storage configuration. Do not reuse example placeholders as real credentials.

## First owner

Open Studio's setup flow. A clean local installation stores the one-time token at `.data/bootstrap.token`; never commit it. Enter it with your name, email, password and organization. After setup the file is removed, Studio opens sign-in, and setup cannot create another owner. Passwords require at least 12 characters. Production requires injected master/bootstrap/worker secrets and administrator MFA.

## Verify your installation

```sh
bun run qb doctor --directory .
bun run check
bun run build
```

Doctor is redacted inventory, not a live provider certification. The optional `bun run spike` checks integration candidates but does not make GraphQL/vector product capabilities available. See [compatibility](/docs/reference/compatibility) and [production deployment](/docs/self-hosting/deployment).
