# Feature roadmap

## P0 foundation

Organizations, projects, primary databases, migrations, protected REST access, application auth, row events, basic S3 storage, SDKs, CLI, audit records and backups form the foundation. The repository verification report tracks whether each release gate has passed.

## P1 developer platform

Planned work includes GraphQL with REST policy parity, magic links/OTP, more certified social providers, database webhooks, presence/broadcast channels, resumable uploads, transforms and general snapshot branching. Approved relationship-existence policies are already implemented in P0.

Vector search, provider-neutral AI, permission-aware ingestion, isolated Bun functions and hosted OAuth MCP require additional native/runtime certification. They are not available simply because their navigation item exists.

## P2 advanced operations

SSO, OAuth identity-provider behavior, replicas, CDN integration, analytics buckets, regional placement, RAG workflows, Deno functions and Terraform follow separate authorization and recovery gates.

## Architecture baseline

Read the [complete development specification](/docs/reference/development-spec) for platform design, requested capabilities, phased contracts and threat-model requirements. It is a baseline specification, not a claim that every phase is implemented.

## Specification 1.1 supersedes the earlier phase assignments

The [expanded release](/docs/roadmap/expanded-release) requires all twelve production/developer workflows, native/offline/background/push and four optional browser WASM integrations as one release. Sections 31–37 of the [generated development specification](/docs/reference/development-spec) take precedence over conflicting historical P0/P1/P2 assignments. Broad GraphQL/AI/connectors/distributed ownership remain deferred candidates. Product version is still 0.1.0; an early foundation is not release completion.
